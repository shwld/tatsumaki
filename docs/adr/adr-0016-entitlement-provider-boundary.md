## Context

[ADR-0015](adr-0015-project-scoped-billing.md) はプロジェクト単位の利用制限と、その権利の取得を同時に定めた。本体が権利を得る手段を知っているため、利用制限の判定、画面、作成や譲渡の復旧に提供者の事情が混ざっている。

## Decision

### 責任の分担

- 本体はプロジェクトの閲覧、書き込み、エクスポート、作成と所有の可否を決めて強制し、利用状態を本体の言葉で表示する。画面は本体が持つ。通常の認可も本体が行う。
- 権利の提供者は、可否、期限、使える操作とその移動先を返す。権利をどう得るかは提供者だけが知る。
- 金額、支払い方法、請求書、解約と購読の手続きは Stripe の画面で扱い、本体は表示しない。次回請求の表示はやめる。提供者に利用者向けの画面は作らない。
- 決済の判断(利用可否と期限の導き方、操作ごとの移動先)は提供者側の ADR に置く。
- セルフホストは提供者を持たず、従来どおり制限なしで動く。

### 本体が聞くことと返る値

| 聞くこと | 渡す値 | 返る値 |
| --- | --- | --- |
| プロジェクトの利用状態 | projectId | 可否、期限とその種類、revision、キャッシュの有効期間 |
| 使える操作 | 利用者の ID、projectId の一覧、表示言語 | プロジェクトごとの操作の一覧と案内、利用者全体の操作 |
| 操作の移動先 | 利用者の ID、対象、操作、戻り先 | HTTPS の URL |

- 可否は「書き込みとエクスポートを許すか」の 1 つ。作成と所有の可否の契約は、作成と譲渡を移すときに加える。
- 期限は、何もしなければ利用できなくなる時刻が分かる場合だけ返す。種類は `ending`(終了が確定)と `action_required`(期限までの操作で利用を続けられる)。更新されうる期限は返さない。
- プロジェクトの操作は `resume`(利用を再開する)、`resolve`(利用を続けるための手続き)、`stop`(利用を終了する)、`manage`(管理)。利用者全体の操作は `manage`。
- 移動先は一覧に含めず、利用者が操作を選んだときに取得する。移動先の有効期間が短いため。本体はその URL へ直接移動する。
- 本体の状態表示で言い表せない案内が必要な場合だけ、提供者が書式のないテキストと HTTPS の URL を返す。

### 本体の確認と表示

- 本体は操作の対象者(所有者)を認可してから提供者に聞く。提供者は呼び出した利用者自身が持つ権利だけを操作の対象にする。
- 本体は返っていない操作のボタンを出さない。移動先と案内の URL は HTTPS だけを使う。
- 状態は「利用できる」「期限まで利用できる」「読み取り専用」「確認できない」で表示する。

### 解約の予約

解約の予約は専用の状態を持たず、種類が `ending` の期限として表示する。取り消しは `manage` の移動先で行う。

### 取得できないとき

- 利用状態は、提供者が返す有効期間だけキャッシュする。取得に失敗した場合は提供者が定める期間まで古い値を使い、それを過ぎたら読み取りを続け、書き込みとエクスポートを拒否する。古い revision の応答は採用しない。期限を過ぎた状態は、キャッシュの期限内でも利用不可と扱う。
- 使える操作を取得できないときは、ボタンを出さず、取得できないことを表示する。
- 作成と所有者の切り替えは、可否を確認できなければ進めない。

### 出来事の通知

- 本体は作成、削除、改名、所有者の変更の結果を提供者へ通知する。再送しても同じ結果になるよう識別子を持たせる。
- 削除は提供者が受け付けるまで再試行する。
- 改名の通知に失敗しても改名は成功させ、後で再送する。

### 権利の取得と所有者の切り替えがずれた場合

- 譲渡は申請と受け手を区別して可否を確認し、本体は所有者の切り替えを一度だけ確定する。所有者がいなくなる状態は作らない。
- 切り替えの成否は永続化して提供者に再送し、遅れて届く結果も申請と照合する。成立しなかった譲渡で取得された権利の後始末は提供者が行う。

### 移行

新しい契約を提供者に先に追加し、本体の移行後に古い契約を削除する。利用状態と操作を先に移し、作成・譲渡・削除・改名は後で移す。

## Consequences

- 本体の判定と表示は提供者固有の取得方法から独立する。一方、契約の変更時は両者の移行順と失敗時の復旧を維持する必要がある。
- 利用者は金額と次回の請求を本体で確認できず、`manage` の移動先で確認する。
- 利用制限の例外、キャッシュの有効期限、所有者切り替えと通知の競合を自動テストで確認する。
- 作成と所有の可否を提供者に確認し、作成・削除・改名・譲渡の結果は本体に記録して再送する。本体は精算の状態を持たない。

### 既存の譲渡からの移行

提供者に新しい契約を先に追加する。本体の移行前に新規取得と譲渡の受付を停止し、旧精算の未完了と要確認がないことを確認する。本体の migration は未完了の旧精算が残ると失敗する。移行後に旧契約を削除する。
